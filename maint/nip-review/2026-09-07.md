# NIP changes since the last Net::Nostr release

Reviewed on 2026-09-07 (America/New_York). The merged CI changes are on local
`main` at `eb42a6dc8520b30ac4bb3591cbc39d89ba151b21`. The ignored `nips/`
checkout was fast-forwarded to
`c3fd9af17939316bf6d0d83a5759100f8b0a1bdb` (2026-09-04).

The highest-priority work is the new NIP-78 privacy recommendation, followed
by NIP-22 comment compatibility and acceptance of hinted EOSE messages.
NIP-29 is the largest feature update. NIP-47 needs extension discovery and
documentation changes. NIP-01's zero-limit clarification already matches
the tested implementation.

## Changed supported NIPs

| NIP | Spec change | Implementation assessment |
| --- | --- | --- |
| [01](../../nips/01.md) | A zero-limit filter MUST return no stored events; EOSE and subsequent live delivery remain required. | Already works in direct relay-handler probes, including a mixed-filter request and configured default/max limits. The store has a zero-limit regression test; add a dedicated wire-level conformance test for the complete EOSE/live sequence. |
| [22](../../nips/22.md) | Removes the prohibition on kind-1111 comments replying to kind-1 notes. | `Comment->comment` still throws for kind 1. Its POD and `t/nip/22.t` explicitly preserve the old prohibition. Change the builder, documentation, and tests; NIP-10 remains available. |
| [29](../../nips/29.md) | Invite suffixes, pin lists, banner metadata, subgroups, and migration/fork guidance. | New invite identifiers fail parsing. Metadata builders reject new fields and the metadata parser discards them. Dedicated pin-list and subgroup behavior is missing. Details below. |
| [34](../../nips/34.md) | Removes GRASP hosting/push instructions from the pull-request section. | No event-schema change. `Git.pm` builds/parses events and does not perform these pushes. No behavioral change identified in the affected helpers or POD. |
| [42](../../nips/42.md) | Permits the NIP-67 `auth` EOSE hint; a relay using it MUST send the AUTH challenge first. | `Message->parse` rejects any three-element EOSE, and Client consequently drops the message before its EOSE callback. NIP-67 is not currently advertised; this is an existing extension-compatibility gap made newly relevant by the NIP-42 change. |
| [46](../../nips/46.md) | Unknown or unsupported remote-signing methods MUST receive an error response. | Existing payload helpers preserve the request ID and construct/parse an error response. There is no signer request-dispatch service in this module to enforce automatic replies. Add caller guidance and a focused unknown-method/error round-trip test. Do not introduce a parser whitelist that prevents a service from replying to unknown methods. |
| [47](../../nips/47.md) | Reduces the core to five commands and moves advanced features to NWC extensions. Adds extension discovery. | `info_event` silently ignores an `extensions` argument, `parse_info` ignores the tag, and the Info object has no extension accessor. Preserve existing generic methods and notification APIs while adding discovery and updating their spec references. |
| [51](../../nips/51.md) | Adds favorite follow sets: kind 10011, with `a` references to kind-30000 sets. | The generic List helper already constructs and parses a valid example. Add explicit tests and documentation; no new event representation is needed. This does not establish comprehensive kind-specific tag validation. |
| [78](../../nips/78.md) | Relays SHOULD require AUTH to accept/serve kinds 78 and 30078, and SHOULD serve them only to the authenticated event owner. Clarifies these kinds are private application storage. | The default relay accepts an unauthenticated publication, returns it to an unauthenticated reader, and broadcasts it to another authenticated identity. Confirmed for both kinds. This is a new SHOULD-level recommendation, not a new MUST. |

## NIP-29 work to separate into manageable changes

1. **Group references and metadata:** parse and format `naddr...?invite=...`,
   pass the invite code to the existing join-request helper, and support
   `banner`, `parent`, and ordered `child` metadata. Parsing an ordinary
   naddr and serializing the existing `previous` tag already work; the new
   `previous` example introduces no new wire representation.
2. **Pins:** add kind-9010 `update-pin-list` and relay-generated kind-39005
   helpers. The ordered list may mix `e` and `a` references and may be empty.
   Accepted updates replace the entire list. Pin limits are optional.
3. **Subgroups:** model a relay-scoped tree, at most one parent, and ordered
   children. Relay enforcement must reject self/cyclic parenting, missing
   parents, and parents the author does not administer. Reparenting updates
   both sides; deleting a parent promotes children to roots. Child-list edits
   must include every child. Membership and administration remain independent
   for each group. `RelayInfo` already preserves the `nip29.subgroups` extension
   through a JSON round trip, but advertising it requires actual support.
4. **Migration and forks:** describe the same group ID on different relays,
   cache administrator keys, and use kind-10009 lists to discover changed
   relay hints. The spec now requires checking those lists when the primary
   relay is unreachable and recommends periodic checks, user notification,
   and history replication.

The existing Group module is a set of event/identifier helpers. The general
Relay does not currently implement a NIP-29 group moderation/state engine,
and Client does not implement a group migration workflow. Adding helpers
alone would not satisfy the new relay and application responsibilities.
Tests, POD, and advertised support must distinguish those scopes.

## NIP-47 and the external NWC specifications

The [NWC repository](https://github.com/nostr-wallet-connect/nwc/tree/6b408adedbd38da584035f949c48a368a792bd8b)
was checked out separately at `6b408adedbd38da584035f949c48a368a792bd8b`
(2026-08-26). It reserves `01.md` for a future standalone core spec; the
current core remains NIP-47.

The five core methods are `pay_invoice`, `make_invoice`, `lookup_invoice`,
`get_balance`, and `get_info`. Existing features moved as follows:

| [03](https://github.com/nostr-wallet-connect/nwc/blob/6b408adedbd38da584035f949c48a368a792bd8b/03.md) | Hold-invoice commands and notifications |

| [05](https://github.com/nostr-wallet-connect/nwc/blob/6b408adedbd38da584035f949c48a368a792bd8b/05.md) | Transaction history; the current extension also includes optional `total_count` |
| [06](https://github.com/nostr-wallet-connect/nwc/blob/6b408adedbd38da584035f949c48a368a792bd8b/06.md) | Metadata conventions and limits |
| [07](https://github.com/nostr-wallet-connect/nwc/blob/6b408adedbd38da584035f949c48a368a792bd8b/07.md) | Mobile pairing deep links |

The repository also contains optional [NWC-321](https://github.com/nostr-wallet-connect/nwc/blob/6b408adedbd38da584035f949c48a368a792bd8b/321.md),
introducing BIP-321 Lightning `pay` and `receive` methods. This would be a
separate support decision, not a prerequisite for retaining NIP-47 core
support. Its complete payment-processing dependencies were not audited.

Add extension identifiers to info-event construction and parsing, expose
them in the Info object, and cover them in `get_info` result examples and
round trips. Keep legacy notification discovery and existing method payloads.
Moving a feature out of NIP-47 core is not evidence that its public API should
be deleted. Do not hardcode the extension examples as a complete registry:
NIP-47 currently mentions `08`, while the checked-out NWC repository has no
`08.md`.

## Suggested implementation order

1. **NIP-78 privacy policy.** Add authentication and owner-based access for
   both kinds, with explicit behavior and migration documentation. Cover
   unauthenticated users, authenticated non-owners, multiple authenticated
   identities, stored queries, live subscriptions, and publication. Review
   COUNT and negentropy too, since those paths currently query the store
   without an owner policy. This is a behavior change for existing public
   app-data use, so its defaults or any deliberate opt-out need to be explicit.
2. **NIP-22 plus EOSE interoperability.** Replace the obsolete kind-1 rejection
   test, add round trips, and accept valid EOSE hint arrays without losing the
   end-of-stored-events notification. If implementing hint emission, cover
   AUTH-before-EOSE ordering and NIP-67's other requirements before advertising
   that NIP.
3. **NIP-47 extension discovery.** Preserve current APIs; update tests and
   documentation to identify their new specification locations.
4. **NIP-29 in the separate scopes above.** Start with references/metadata and
   pin event helpers, then scope relay enforcement and migration behavior.
5. **Small coverage/documentation updates.** Explicitly cover NIP-01 zero-limit
   subscriptions, NIP-51 kind 10011, and NIP-46 unknown-method errors. Record
   the NIP-34 editorial change. Evaluate NIP-A3 and the unadvertised NIPs as
   separate feature work.

Keep the current conformance target in README and POD until this work has
been implemented and checked against the relevant NIP requirements. A newer
local specification checkout does not establish conformance.

## Verification and limits

The [observation script](2026-09-07-probe.pl) and
[recorded output](2026-09-07-results.json) contain 16 observations on `main`.
They exercise public helpers and direct relay handlers using signed events
and capturing connections. Relay connection/authentication state is supplied
in memory; these probes do not exercise the WebSocket or AUTH handshakes.
The script catches errors to record them, so its zero exit status is not a
conformance pass. The rejected inputs and missing fields in the JSON are
confirmed gaps against the new requirements or optional features.

With matching Perl dependencies available, run from the repository root:

```sh
perl -Idist/Net-Nostr-Core/lib -Idist/Net-Nostr-Relay/lib \
  -Idist/Net-Nostr-Core/t/lib maint/nip-review/2026-09-07-probe.pl
```

Validation used Linux Perl 5.44.0 with isolated dependency directories under
`/tmp/net-nostr-key-permissions/` and `/tmp/net-nostr-websocket-investigation/`.
AnyEvent::WebSocket::Server 0.10 was loaded from its previously downloaded
source tree. The older repository-local XS cache was not mixed into this Perl.

Logs and downloaded release metadata/archives are under
`/tmp/net-nostr-nip-review/`. Existing passing tests target older behavior;
they do not negate the gaps recorded by the probes.

No library implementation, public API, validation behavior, POD, or
distribution `Changes` was modified by this audit. The report, probe, and
observation JSON are the only new project files. No release or PR was created.
This was a review of changed requirements, not a fresh line-by-line audit of
all 56 supported NIPs or all optional NWC extensions. Full Core tests, new
wire-level regression tests, external interoperability tests, and platform
matrices were not rerun for this research-only work.
